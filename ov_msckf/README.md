# ov_msckf

MSCKF-based visual-inertial estimator. See the [top-level README](../ReadMe.md) and
[docs.openvins.com](https://docs.openvins.com/) for the general project overview.

## GPS fusion

`ov_msckf` can optionally fuse GPS fixes directly into the MSCKF filter — single-filter and
position-domain, i.e. **loosely coupled but not cascaded**. When a fix arrives the filter propagates
the real IMU state to its exact timestamp, clones a stochastic pose there, runs a chi2-gated EKF
update against the fix, and marginalizes the clone again. No pose is ever interpolated.

**→ [Design notes: derivation, rationale, measured results and tuning](../docs/gps-fusion.md)**

This page covers usage only.

### Enabling it

Set `gps_enabled: true` in your `estimator_config.yaml`. See
[`config/gps_example/`](../config/gps_example/) for a fully commented starting point, or the `gps_*`
block in [`config/rpng_sim/estimator_config.yaml`](../config/rpng_sim/estimator_config.yaml) for a
simulation-ready example. Every option is listed in
[the design notes](../docs/gps-fusion.md#13-configuration-reference) and declared in
[`UpdaterGPSOptions.h`](src/update/UpdaterGPSOptions.h).

With `gps_enabled: false` (the default), behaviour is unchanged from vanilla OpenVINS, and `ov_core` /
`ov_msckf` outside `src/ros/` still build and run standalone.

Key things to set for real hardware:

| Option | Why it matters |
|---|---|
| `topic_gps` | The `sensor_msgs/NavSatFix` topic to subscribe to. |
| `gps_noise_floor` | **The parameter most likely to break your run.** Set it to the full error budget (VIO drift + lever-arm + transform + time-sync error, typically 0.5–2 m), *not* the receiver spec. Too low and the chi2 gate rejects everything, silently. See [§6](../docs/gps-fusion.md#6-the-chi2-gate). |
| `gps_leverarm_prior` | The antenna's offset from the IMU, in the IMU frame (metres). Set `gps_do_calib_leverarm: true` to estimate it online if you cannot measure it precisely. |
| `gps_datum` | Optional fixed `[lat, lon, alt]` datum for the local ENU frame. Defaults to the first fix with a valid status lock. |
| `gps_init_min_baseline` / `gps_init_min_excursion` | How much *non-collinear* 2D motion is needed before the ENU-to-global transform is initialized. The yaw is unobservable along a straight line, so these gate on genuine 2D spread, not distance travelled. |

### What gets published (ROS1/ROS2)

- Fixes are converted from WGS84 LLA to the local ENU frame on the ROS side
  ([`gps_conv.h`](../ov_core/src/utils/gps_conv.h) — a small self-contained WGS84 conversion, no new
  dependency).
- `pathenu` — the trajectory of received fixes, in the ENU frame.
- An `enu -> global` TF once the transform is initialized, so GPS and VIO trajectories can be overlaid
  in the same frame in rviz.
- `gps_datum_lat/lon/alt` echoed back as ROS parameters once the datum is set.

### Tests

Built as executables alongside the module:

| Executable | Covers |
|---|---|
| `test_gps_jacobians` | Analytical vs. numerical Jacobians for the measurement model; the closed-form yaw/translation (Horn) solve against a synthetic known transform. |
| `test_gps_clone_cycle` | The clone → update → marginalize bookkeeping, including delayed init and the PPS coincident-clone case; checks `_clones_IMU` and covariance PSD/symmetry. |
| `test_gps_sim` | Full-simulation integration: transform convergence, ATE with vs. without GPS, NEES consistency, robustness to IMU timestamp jitter, and rejection of injected outliers. |

Synthetic GPS is generated by `Simulator::get_next_gps()` from the same B-spline ground truth as the
camera/IMU streams (`sim_freq_gps`, `sim_gps_*`), and fed through `VioManager::feed_measurement_gps()`
exactly as a real ROS callback would.

> When `gps_enabled` is true all three simulated streams race so they interleave in true timestamp
> order — you must poll `get_next_gps()` every loop iteration alongside `get_next_imu()` /
> `get_next_cam()`, or the timeline stalls. `test_sim_repeat` / `test_sim_meas` never touch GPS and
> must be run with `gps_enabled: false`.

### Evaluation

[`scripts/gps_eval/`](scripts/gps_eval/) runs VIO-only vs. GPS-fused vs. simulated-outage variants
against a real bag and produces a report. Its README documents the ground-truth circularity caveat —
when GNSS *is* the reference, only the runs that withheld fixes from the filter measure real accuracy.
